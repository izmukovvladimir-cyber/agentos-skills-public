# Критерии отбора рилсов

## Главное правило

**«Разговорные, легко переснимать.»**

Берём ТОЛЬКО форматы где владелец может:
1. Записать голос за кадром
2. Монтажёр накладывает голос на оригинал или близкое демо
3. ИЛИ через Higgsfield/FAL воспроизвести визуал (если Soul ID владелец работает)

## Конкретные ✓ форматы

- Split-screen — top half профиль/screen-record, bottom half talking head
- Screen-record процесса (IG-настройки, Claude интерфейс, любое приложение)
- Talking head + графические оверлеи (текстовые карточки, цифры, заголовки)
- Voice-over на AI-генерации (Higgsfield Soul + Seedance)

## Конкретные ✗ форматы

- Уникальная обстановка (аэропорт, машина клиента, шоу-сцена)
- Гость в кадре которого мы не повторим
- Сложная графика / motion-design без шаблона
- Talking head в специфическом месте который у владельца не пересмотреть

## Скоринг (композитный, формула владелец)

Каждый рилс получает сумму баллов. Полная доктрина и логика 5 сигналов — в `SKILL.md` секция «HARD RULE — формула виральности и отбор». Веса в `config/watchlist.json:scoring{}`:

| Признак                                   | Баллы | Ключ |
|-------------------------------------------|-------|------|
| Просмотры > 3× медианы автора (ГЛАВНЫЙ)   | +30   | viewable_above_3x_median |
| Комменты с триггер-словом (>10 шт)        | +25   | comment_with_trigger_word_gt10 |
| Объём комментов > 300                     | +25   | comment_volume_gt300 |
| Просмотры > 1M абсолют                    | +20   | views_gt_1M |
| Возраст < 48 часов                        | +20   | fresh_under_48h |
| Скорость набора сильная (views/ч)         | +20   | speed_strong |
| ER > 5%                                   | +15   | er_gt_5pct |
| Объём комментов > 100                     | +15   | comment_volume_gt100 |
| Просмотры > подписчиков (БОНУС, не гейт)  | +15   | views_over_followers |
| Скорость набора умеренная                 | +10   | speed_moderate |
| Длина 24-60 сек                           | +10   | duration_24_60s |

Сортируем по сумме → топ 10-15 идёт в визуальный фильтр (Я смотрю глазами).

**Принцип (важно):** ни один признак не «ворота». `views_over_followers` ЛОМАЕТСЯ на крупных аккаунтах (500к подписчиков, виралка за сутки 80к < подписчиков) → он только БОНУС. Главный измеритель = ролик относительно СВОЕЙ нормы (median_x3) + скорость набора. Скорость чинит «крупный за сутки не успел набрать абсолют». Воронка (кодворд + объём комментов) — тяжёлый вес, цель = подписчики + кодовые слова.

**PROTECTED TOP-N :** сильнейшие N роликов дня (`protected_top_n`=6) помечаются `protected` мульти-осево (топ по комментам / показам / скорости / ratio, резерв лидера каждой оси) и входят в пак ВСЕГДА — author/theme-дедуп Блока А к ним не применяется. По сырым осям, не по пороговому `comment_volume` (он уравнивает 350 и 5013 комментов). См. SKILL.md «PROTECTED TOP-N».

## Скоринг каруселей (композитный)

Карусели скорятся ТОЙ ЖЕ композитной логикой, что рилсы (раньше был примитив: лайки×медиана + свежесть). У альбомов нет views → метрика = `like_count + comment_count`. Веса из того же `scoring{}`:

| Признак                                    | Баллы | Ключ |
|--------------------------------------------|-------|------|
| Объём комментов > 300 (ГЛАВНЫЙ)            | +25   | comment_volume_gt300 |
| Лайки > 3× медианы автора                  | +30   | viewable_above_3x_median |
| Скорость набора сильная (eng/ч ≥150)       | +20   | speed_strong |
| Возраст < 48 часов                         | +20   | fresh_under_48h |
| Объём комментов > 100                      | +15   | comment_volume_gt100 |
| Вовлечённость cm/lk > 2%                    | +15   | (engagement) |
| Скорость набора умеренная (eng/ч ≥50)      | +10   | speed_moderate |

- Скорость каруселей = `eng_per_hour = (лайки+комменты)/час`, пороги `carousel_speed_strong_eph=150` / `moderate_eph=50` (НЕ views/ч рилсов).
- Окно свежести **72ч** (`carousel_lookback_hours`, было 120).
- **БЕЗ лимита на автора** — ранжир чисто по вирусности, хоть 5 от одного («нужны вирусные»).
- protected_top_n применяется и к каруселям (оси: комменты / скорость / лайки / ratio к медиане).

## Метрики в карточке

Обязательно:
- Просмотры (живая цифра + сравнение с нормой автора «×N к медиане»)
- Подписчики автора + перелетел ли аудиторию (views > followers)
- Скорость набора (views/час)
- Лайки + ER
- Комменты (общее число + сколько с триггером отдельно)
- Есть ли кодовое слово (воронка)
- Длина в секундах
- Возраст в днях

**НЕДОСТУПНО со стороны (проверено ):** сохранения (saves) и репосты (shares) IG отдаёт ТОЛЬКО владельцу аккаунта в его Insights. `/v1/media/by/code` = play/like/comment. Прокси пересылок = «просмотры > подписчиков».

Опционально (если HikerAPI отдаст):
- % досмотра (avg watch time / duration)

## Виральность «к норме автора»

Считается:
1. Берём последние 30 рилсов автора
2. Считаем медиану просмотров
3. Делим текущий рилс на медиану → коэффициент

Пример: автор обычно делает 20к, этот сделал 374к → ×18.7 к норме = «он сам выстрелил выше потолка». Это сильнее чем абсолютная цифра.

## Триггер-слова в комментариях (сигнал конвертации)

Парсим комментарии текущего трендового триггер-слова (см. `config/watchlist.json -> active_trigger_word` и `trigger_word_variants_for_comment_signal`).

Если у рилса >10 комментариев с триггер-словом — он реально работает на воронку. Это сильнее чем просмотры.
