# niche-reels-research

Авторская методология поиска и адаптации виральных рилсов под аккаунт владельца. Двухслойная схема с надстройками под нашу нишу.

## Цель

Каждое утро пн-пт без участия владельца выдавать готовый пакет на запись:
— до 10 разговорных рилсов из watchlist (свежие, конвертящие, дедуплицированы)
— до 10 каруселей параллельно (минимум 5)
— **РИЛС**: метрики + почему взяла + хук + телесуфлёр (рерайт по HARD RULE «объём и язык»: EN=дословный перевод, RU=фрирайт 20-25%, НЕ сокращать) + капшен + ТЗ монтажёру + ссылка на оригинал
— **КАРУСЕЛЬ (HARD, владелец): только сам референс + виральность + почему выбрала + ссылка. БЕЗ телесуфлёра и БЕЗ ТЗ монтажёру** (карусель не снимают и не монтируют). Зашито механически в `send_morning_digest.py` (`card_html` гейтит телесуфлёр/ТЗ по `type=="carousel"`). Рилсовый формат НЕ менять.

владелец тратит 5-10 минут утром, выбирает на запись, читает голосом, отдаёт монтажёру. После — одной строкой говорит мне «N взял / M отклонил» → я апаю state дедупликации.

## Архитектура (двухслойная)

### Слой 1 — РУЧНОЙ
- Дрессирует IG-ленту: смотрит 20-30 рилсов в нише до конца, подписывается на новых
- Раз в неделю кидает мне в чат 1-3 новых кандидата для расширения watchlist
- Утром выбирает 1-2 из готового пакета на запись

### Слой 2 — АГЕНТСКИЙ (я)
- Пн-пт 03:00 МСК парсю watchlist через HikerAPI (delta-mode)
- Скорю → фильтрую → дедуплицирую (исключаю taken / rejected из state) → транскрибирую через Groq
- Пишу карточку + хук + телесуфлёр + CTA + ТЗ монтажёру
- К 08:00 МСК отправляю пакет в Telegram через `send_morning_digest.py`

## Watchlist

**Список доноров ведёт владелец под свою нишу.** См. `config/watchlist.json` — единственный
source-of-truth, читать оттуда перед каждым прогоном. Структура: `anchor_accounts` (ядро прямых
конкурентов, 5-10 штук), `expansion_accounts` (проверяемое расширение), `carousel_accounts`
(ОТДЕЛЬНЫЙ список под карусели), `rejected` (отсеянные, чтобы не вернулись случайно). В файле
лежит шаблон с примерами, заполняется руками. Добавленные аккаунты не выкидываются молча:
отсев идёт через `rejected` с причиной.

Рабочий размер: 40-60 аккаунтов, цель роста 100-200.

Лимит до 60. После 14 дней без виралок (≥3× медианы) аккаунт переходит в `rejected`.

**При добавлении нового аккаунта** (владелец говорит «добавь X»):
1. Onboarding analysis: последние 24 поста через `reels-analyzer`
2. Считаю baseline-медиану
3. Записываю в watchlist.json и `cache/watchlist_baseline.json`
4. Со следующего дня — включается в утренний свежак

## Критерии (см. references/criteria.md)

**Фильтр №1 (скоринг, автомат):**
- +30 за просмотры > 3× медианы аккаунта
- +25 за коммент с триггер-словом «статья / гайд / промпт / ПАК» (> 10 шт)
- +20 за просмотры > 1M
- +20 за возраст < 48 ч
- +15 за ER > 5%
- +10 за длину 24-60 сек

Топ-10 по скору → визуальный фильтр.

**Фильтр №2 (визуал, я смотрю кадры):**
✓ Берём: split-screen / screen-record / talking head + графика
✗ Отсеиваем: сложная графика / уникальная обстановка / иностранный гость

**Фильтр №3 (обработка):** топ-5 → транскрипт → рерайт → пакет.

## HARD RULE — формула виральности и отбор (владелец, обсуждено и утверждено 🤝)

Эта секция уточняет Фильтр №1 выше. Следуем ей КАЖДОЕ утро.

**Цель отбора (дословно владелец):** виральные ролики ЗА ПОСЛЕДНИЕ СУТКИ, которые владелец ПОВТОРЯЕТ и наберёт подписчиков + кодовые слова. То есть = рабочий формат (повторишь → взлетит) + воронка (кодовое слово в комментах). НЕ просто «много просмотров».

**Один признак не работает:** «просмотров больше подписчиков» ЛОМАЕТСЯ на крупных (500к подписчиков, сильный ролик за сутки 80к < подписчиков, но это виралка). Поэтому мерим КОМПОЗИТОМ и сравниваем ролик С ЕГО СОБСТВЕННОЙ нормой, а не всех под одну линейку.

**Пересылки и сохранения НЕДОСТУПНЫ со стороны** (IG отдаёт их только владельцу в Insights; `/v1/media/by/code` = play/like/comment). Прокси пересылок = просмотры > подписчиков. Захвачено в `pull_reels.py` без доп-вызова: `follower_count`, `views_over_followers`, `views_per_follower` на каждом ролике (из `/v1/user/by/username`, который pull и так делает).

**Композитная формула (5 сигналов, ни один не «ворота», складываются в балл), окно 24ч приоритет:**
1. **ГЛАВНЫЙ — выше своей нормы:** `views / медиана автора`. Работает на любом размере аккаунта (это компонент median_x3). Чинит проблему крупных.
2. **СКОРОСТЬ:** `views / час` с момента выхода. Чинит «крупный за сутки не набрал 100к» — судим по ТЕМПУ, не итогу. Снимает старый конфликт «свежак <48ч ещё не набрал просмотры» (см. секцию окна) — ранний разгон ловим по pace. Новое поле `views_per_hour` (делегировано <agent>).
3. **ВОРОНКА:** кодовое слово в комментах (триггер) + абсолютный объём комментов. Для владельца ключевое — его механика = подписчики + кодовые слова.
4. **БОНУС (не гейт, ~15 не доминанта):** `views_over_followers`. На мелких/средних срабатывает, крупных не наказывает.
5. **ПОРОГ снизу** по просмотрам — отсечь шум.
Веса в `watchlist.json:scoring{}`. Авто-вес делегирован <agent> (swarm 046056c2 / 813827d8: views_over_followers НЕ доминанта, + views_per_hour, + бонус за объём комментов). До зашивки — ранжирую этими сигналами вручную при отборе.

**Глубина на аккаунт:** брать ВСЕ свежие ролики за окно, НЕ фикс-число. Большинство постит 1-3/день. Потолок `limits.reels_per_account` (=12) только чтобы не раздувать прожорливых. (3 было багом — отсекало 4-5-й виральный ролик до скоринга; теперь захват подписчиков + глубина из конфига, `pull_reels.py.bak-20260624-daria-depth8`.)

**Воронка отбора:** 47 аккаунтов → все свежие за 24ч (~80-150 роликов) → композитный скор → топ 10-15 → Я СМОТРЮ ГЛАЗАМИ (хук / формат / повторяемость / воронка) → финал ≤10 рилсов + ≤10 каруселей. Топ ОБЯЗАТЕЛЬНО проверять глазами самой, не отдавать целиком субагенту.

**Покрытие:** проверять, что все аккаунты скачались; упавшие до-качивать; в сводке строка «прогнал X из N» (делегировано <agent>, `_coverage.json`). Молчаливый сбой скрейпа = потерянные виралки.

## Конвертность донора и мёртвый призыв (<agent> , поручение владельца от 22.08)

Повод: у одной из клиенток отбор доноров переведён с просмотров на конвертность, комментарии
на 1000 просмотров, у каруселей на 100 лайков. владелец велел забрать этот ключ, когда наши
IG-воронки снимут с паузы. 24.08 автоматики сняли (127 живых из 147), значит условие наступило,
и замер сделан.

**Главным ключом конвертность НАМ не годится, и это счёт. Мнения тут нет.** На нашем пуле 26.08
(74 рилса, 53 аккаунта) она меряет наличие кодворда в капшене, силу формата она не показывает: медиана 17.33
у роликов с призывом против 0.64 без него, в топ-10 по конвертности 10 роликов из 10 с призывом.
Отбор по ней вырезал бы русский виральный сегмент целиком, включая ролики на 385, 272 и 229
тысяч показов, то есть ровно тот холодный охват, ради которого фронт-энд и существует.
Пересечение живого топ-10 с топ-10 по конвертности вышло 3 из 10.

**Что взято вместо этого: предохранитель на мёртвый призыв.** Если автор ЗОВЁТ писать слово, а
идти на призыв не идут, копировать у него нечего: формат людей не двигает. Такой донор получает
штраф 25 и уходит вниз. Ролики БЕЗ призыва правило не трогает вовсе. Виралка с испорченным
капшеном всё равно проходит по охвату, потому что это штраф. Воротами он не работает.

**Порог ОТНОСИТЕЛЬНЫЙ, треть от медианы конвертности призывных роликов ЭТОГО пула.** Фиксированного
быть не может: разброс медианы по восьми отделам двадцатикратный (AI 17.45, отношения 0.84,
психология 0.82, ипотека 0.73). Порог 5, снятый с ниши AI, пометил бы мёртвыми 87-94 процента ВСЕХ
призывов у трёх клиентов, то есть выродился бы в наказание за сам призыв. Проверка на восьми пулах
после перехода на относительный порог: помечено 0-9 на пул, топ-10 совпал 10/10 везде.

**Меньше 8 призывных роликов в пуле, и правило молчит, говоря об этом строкой.** Ноль помеченных
при живом правиле и ноль при отсутствии выборки снаружи выглядят одинаково.

**Признак призыва снят узко, в два условия сразу:** глагол письма на границе слова И рядом либо сам
кодворд (капсом или в кавычках), либо прямое указание места (ком:менты, директ, личные). Широкий
шаблон ловил «Запишите ребенка на курс» и «пишите помощнице» из вакансии на 1.6 млн показов, оба
получили бы штраф ни за что. Отдельная грабля того же захода: общий флаг IGNORECASE делает класс
[A-ZА-ЯЁ] регистронезависимым, и тогда «Пишите ваше мнение» становится призывом.

**Карусели по конвертности НЕ судим.** Выборка 26.08 всего 6 штук, вывода на ней нет, плюс призыв у
каруселей обычно живёт на СЛАЙДЕ, капшен его не содержит, поэтому детектор его не видит по построению.

Настройки: `watchlist.json` → `scoring.dead_cta_penalty` (25), `limits.dead_cta_median_share` (0.33),
`limits.dead_cta_min_views` (1000), `limits.dead_cta_min_sample` (8). Ставится вторым проходом
`mark_dead_cta()` в `score.py` ДО отбора кандидатов на дорогой фетч комментов.

## HARD RULE — off-niche виральные ролики это стратегия, не брак (владелец, голосовое)

Правило действует в ЛЮБОЙ нише, не только у владельца — касается всех, кто судит виральные ролики
по этой методологии (клиентские агенты включительно).

Широкий, не по нише ролик, выложенный в пробном режиме ради холодного охвата — это НАМЕРЕННАЯ
стратегия, не несостыковка и не брак формата. Механика: широкая тема ловит внимание холодной
аудитории (люди, которые в моменте не смотрят экспертный контент ниши), они подписываются,
дальше видят профильный/экспертный контент и остаются по нему. Так росла личная страница владелец
(широкоформатные ролики + профильные рядом), так же работает у любого эксперта в любой нише:
астролог может выложить ролик не про астрологию, коуч не про коучинг — если это приводит холодных
людей, которые потом доходят до профильного контента.

**Что это значит на практике:** не флагуй и не критикуй виральный ролик за «не соответствует
нише» / «не бьётся с экспертизой» — сам по себе такой ролик не проблема. Проверяй как обычно
формат/хук/повторяемость/воронку, но несоответствие теме — не повод отклонить и не повод писать
это как найденную несостыковку. Смотри, чтобы профильный/экспертный контент оставался
количественно основой аккаунта — пробный широкий контент идёт РЯДОМ, не вместо него.

**НЕ ПИСАТЬ «СВЕРИЛ ГЛАЗАМИ», ЕСЛИ НЕ ОТКРЫВАЛ (hard, ).** В карточку пака запрещено писать «я сверила слайды глазами», «проверено визуально» и любую другую заявку о проверке, если превью или сами слайды не были открыты Read-ом в этой же работе. Разбор содержания карусели снимается ТОЛЬКО со слайдов. Подпись автора для этого не годится: у части авторов она одинаковая на всех постах и описывает не тот пост, под которым висит.

Реальный случай, ради которого правило и появилось: пак описал карусель как «шесть слайдов про пак навыков Клода» и отдельной строкой заявил проверку глазами. На слайдах был поиск дешёвых авиабилетов, а навыки Клода упоминались только в дежурной карточке в конце. Тему рекрейта выбрали по выдуманному разбору, и ошибку поймали лишь на этапе отрисовки.

Как писать честно, когда слайды посмотреть не удалось: «содержание снято с подписи, слайды не открывались». Такая формулировка сразу говорит, что разбору верить нельзя, и его перепроверят до того, как он уйдёт в работу.

**Оглавление в паке :** вверху HTML — нумерованный список с быстрым переходом `#itemN` + кнопка «↑ к содержанию» у каждой карточки. Вшито в `send_morning_digest.py` (`toc_html`, `id="itemN"`). Рилсы И карусели. См. [[feedback-morning-pack-quick-jump-links]].

**Карточка ролика показывает (чтобы владелец сразу видел, что повторять):** во сколько раз выше нормы (ratio), просмотры, подписчики, перелетел ли аудиторию, комменты, есть ли кодовое слово, скорость набора.

**Карусели:** окно **72ч** (`carousel_lookback_hours`, было 120 — отсекаем стале многодневные). Скоринг **КОМПОЗИТНЫЙ как у рилсов** (`pull_carousels.py score_account`, веса из того же `scoring{}`): ГЛАВНЫЙ вес — сырой ОБЪЁМ комментов (`comment_volume_gt100/gt300` — вирус + воронка кодворда), плюс СКОРОСТЬ набора `eng_per_hour = (лайки+комменты)/час` (у альбомов нет views; пороги `carousel_speed_strong_eph=150`/`moderate_eph=50`), кратность к медиане автора по лайкам (`viewable_above_3x_median`), свежесть <48ч, вовлечённость cm/lk. **БЕЗ лимита на автора** («нужны вирусные, хоть 5 от одного») — ранжир чисто по вирусности.

**PROTECTED TOP-N — сильнейший ролик дня входит ВСЕГДА .** Косяк 27.06: бэнгер дня `mavgpt DaDfKmuqRyW` (114к показов / 5013 комментов) срезали зря — author-dedup (у автора уже был ролик в паке) + theme-dedup (тема пересеклась с лид-магнитом «разбор лица» 24.06). Soft-фильтр не имеет права ронять выстрел. Механика (пирамида config → флаг → промпт → бэкстоп):
- `score.py` помечает топ-N виралок дня `"protected": true` в `_scored.json`/`_top10.json` (`mark_protected`). Отбор МУЛЬТИ-ОСЕВОЙ: топ-`protected_per_axis` (=3) по каждой оси — комменты, показы, скорость (views/час), ratio к медиане — union, кап `protected_top_n` (=6). Непрерывно по сырым осям, НЕ по пороговому `comment_volume` (он уравнивает 350 и 5013 комментов). Бэнгер, ведущий хоть по одной оси, попадает.
- `_top10.json` = топ по score_total ∪ protected (protected обязаны дойти до глаз <agent>, даже если по score_total ниже обзорного порога).
- Блок А (`daria-morning-trigger.sh` шаг 1b): protected входит в пак ВСЕГДА; author-dedup и theme-dedup применяются ТОЛЬКО к `protected:false`; два ролика от одного автора — ок, если оба protected; off-niche с кодворд-механикой среди protected — берём. Если protected сохранён правилом против дедупа → строка в `meta.json` intro.
- Бэкстоп в `send_morning_digest.py` (`protected_missing_warn`): если protected-код не вошёл в пак — громкий WARN в сводку (<agent> видит, даже если субагент срезал). Зеркало carousel/hook warn, fail-open.
- Пороги в `config/watchlist.json:limits` (`protected_top_n`, `protected_per_axis`).
- **Карусели — тот же protected :** `pull_carousels.py mark_protected_carousels` помечает топ-N каруселей по карусельным осям (комменты / скорость eng-час / лайки / ratio к медиане), `_carousels_top.json` = топ ∪ protected, Блок А шаг 1c (protected всегда в пак, БЕЗ лимита на автора). Бэкстоп `protected_missing_warn` в `send_morning_digest.py` читает и `_scored.json`, и `_carousels_scored.json`.

## ПРАВИЛА ТЕКСТА (HARD, разбор <agent> , распоряжение владельца)

До того как писать хоть строку для людей, прочитай целиком
`~/.claude/skills/_text-rules/TEXT_RULES.md`. Короткая выжимка, чтобы
правила работали даже если файл не открыл:

1. Никаких «Где здесь X и где Y» и «это не про X, это про Y». Плюс прежние запреты: длинное
   тире «—» и оборот «не X, а Y».
2. Живая русская речь. Каждую фразу проверь вопросом «так вообще говорят?». «Часть дружб
   заканчивается» это брак, «часть друзей перестаёт общаться» нормально.
3. Пункт списка это конкретная ситуация целиком, без абстракций. Читатель должен понимать,
   с кем встреча, что отменяем, кто кого избегает.
4. Отсылок назад нет: «как я писала выше», «вернусь к» запрещены, каждый слайд понятен сам.
   Петля ведёт ВПЕРЁД, следующий слайд её закрывает.
5. Термин вводится сразу с расшифровкой, иначе не используется вовсе.
6. Финал и лид-магнит вытекают из разобранного механизма, случайный «просто чтобы был» это брак.
7. Перед выдачей прогони чек-лист из §7 файла: вслух, абстракции, самодостаточность слайда,
   связь финала, вычистка «—» и пар из п.1.

## Шаблон выдачи (см. references/output_format.md)

На каждый рилс — 4 сообщения в Telegram (порядок строгий):

1. **Карточка** (обычный текст, НЕ под копирку) — ссылка на оригинал вверху + метрики + 5 причин почему выбрала + формат оригинала
2. **Телесуфлёр** (`<pre>` под копирку) — произносимый текст с паузами `(пауза 0.3 сек)` / `(пауза 1 сек)` / `(пауза 1.5 сек, вдох)` + проговариваемый CTA в конце. Это то, что владелец ГОВОРИТ на камеру.
3. **Капшен** (`<pre>` под копирку) — короткое ОПИСАНИЕ ПОД РИЛС для вставки в Instagram (~300-450 символов): крючок по теме + value + CTA «статья». ОТДЕЛЬНЫЙ от телесуфлёра текст, НЕ пересказ речи. Маскировка двоеточием, без длинных тире. **ВСЕГДА в подборке вместе с рилсом (hard).**
4. **ТЗ монтажёру** (обычный текст, НЕ под копирку) — сцены 0:00-X:XX с описанием top/bottom half, текста, звука, транзиций + блоки «продукт», «сабтайтры», «музыка». Референс-ссылка вверху.

Под копирку (`<pre>`) идут ДВА блока: телесуфлёр + капшен. Метрики и ТЗ — плоский текст.

**ПРОПУСК: утренний субагент Блока А выдал 8 рилсов БЕЗ капшенов (поле `caption` пустое) → владелец поймал «а капшен к рилсам пишешь?».** Капшен к рилсу = ОБЯЗАТЕЛЬНОЕ поле, не опциональное. **HARD: в JSON-контракте, который даю субагенту Блока А, поле `caption` ОБЯЗАТЕЛЬНО для КАЖДОГО рилс-пака** (крючок+value+CTA «статья» в комментарии, маскировка, тире 0). `send_morning_digest.py` рендерит блок «Капшен под пост» только если `caption` непустой — пустой = брак. Проверять перед доставкой: `grep -c 'Капшен под пост' reels_<date>.html` == числу рилсов. Капшен только для РИЛСОВ; карусели в утреннем пакете = только референс (капшен пишется при сборке НАШЕЙ карусели).

**Кодовое слово CTA — СВОЁ под тему каждого рилса (hard, владелец голос , ОТМЕНЯЕТ старое «только статья» от 06-13):** в телесуфлёре и капшене призыв ведёт на кодворд ПОД ТЕМУ этого рилса (как у каруселей), а НЕ на общую «статья». Под каждый рилс = свой отдельный лид-магнит + выдача (по аналогии со ступенями на курсе): Я САМА собираю воронку (бот → канал → подписка → лид-магнит → выдача) под это слово по стандарту [[feedback-funnel-build-standard-process]] на обеих платформах (IG-бот + TG). «статья» беру ТОЛЬКО когда владелец явно скажет «тут веди на статью» (он предупредит про исключение). Дефолт = слово под обещание рилса, совпадающее с тем, что реально обещано в ролике. **Рассинхрон (рилс обещает одно, кодворд ведёт на другое) = брак: тёплый лид приходит за конкретикой, получает не то и остывает.** Воронка+лид-магнит под кодворд готовятся ВМЕСТЕ с рилсом, не «потом».

## Рерайт телесуфлёра — правило объёма и языка (HARD RULE, владелец голосом )

**НИКОГДА НЕ СОКРАЩАТЬ объём текста.** Телесуфлёр = полный сценарий, по длине не меньше оригинала. Сжатый конспект вместо речи = брак. И НЕ уводить в свою тему: рерайт строго про то же, что в оригинале.

**EN-оригинал → просто ДОСЛОВНЫЙ перевод на разговорный русский.** Никакого рерайта. Перевожу так, как мы говорим вслух по-русски (живой разговорный, не канцелярит), сохраняю ВСЕ шаги, промпты, конкретику и ядро смыслов, полный объём. Примеры/CTA не подменяю своими, перевожу как есть (владелец сам решит, что адаптировать).

**RU-оригинал → лёгкий фрирайт ~20-25%.** Беру текст и слегка переписываю: меняю часть слов, чтобы было не один-в-один, но НЕ меняю длину и НЕ трогаю ядро смыслов. Захватываю чуть-чуть своими словами, остальное как у автора. Без длинных тире.

**ХУК + ЯДРО — ДОСЛОВНО .** Телесуфлёр = адаптация чужого вирального текста, а не новый текст. Хук (первые ~3 сек) оставляю дословно или почти дословно, ядро (смысл, структуру, последовательность) сохраняю. Рерайт ≤25% меняет ТОЛЬКО: табу-слова под IG, чужие @ники и CTA, мат, чужой кодворд на наш. Хук по-своему не переписываю, не пересказываю своими словами, не добавляю свой лид-ин перед хуком — переписанный хук убивает виральную механику. **Проверка:** после сборки packs, до доставки — `python3 scripts/hook_fidelity_check.py` (exit 10 = хук переписан, верни оригинал и пересобери). Иностранные рилсы скрипт помечает skip — для них правило держу сама: хук в переводе по смыслу 1:1. Дублирующий guard стоит в `send_morning_digest.py` (WARN в сводку, если хук переписан).

**Четыре случая, где дословность упирается в потолок** (первые два найдены <agent> 26.07, третий ею же 29.07, четвёртый <agent> 30.07, встретятся у всех):
1. **В хуке звучит имя автора-источника** («Игорь, ты знаешь...»). Чужое имя обязано уйти, значит retention до 1.00 не дотянет никогда, реальный потолок около 0.85-0.90. Это НЕ брак: меняем только имя, остальную формулировку держим слово в слово.
2. **Первые ~14 токенов не авторский хук, а цитата-врезка** (кусок чужой переписки, разбор, зачитка комментария). Тогда дословно сохраняем врезку как цитату, а свой лид-ин перед ней всё равно не ставим. Если врезка тянет в пак чужой регистр речи, лучше отсеять ролик форматом, чем ломать TOV.
3. **ХУК СТОИТ НА ЧУЖОЙ БИОГРАФИИ, и порог недостижим ЧЕСТНЫМ путём в принципе.** Пример: «Я брала интервью Ольги Бузовой, Радислава Гандапаса, Анфисы Чеховой, Ивана Охлобыстина», восемь из четырнадцати контентных слов это имена. Вернуть хук дословно значит приписать своему эксперту интервью, которых не было, а честная версия дала retention 0.09 при пороге 0.50. Здесь гейт хука прямо сталкивается с запретом выдумывать фактуру за эксперта, и **побеждает запрет**.
   **Что делать:** `--force` НЕ трогать, ролик перевести в REFERENCE-ONLY с причиной прямо в карточке и назвать эту причину вслух в подводке. Саму мысль оформить ЗАЯВКОЙ НА СВОЙ ролик на реальной фактуре эксперта, тогда проверка даёт skip и гейт проходится честно. Отличие от случая 1: там уходит одно имя и формулировка держится, здесь на именах стоит вся конструкция хука, и заменить их нечем.
   **Граница с рерайтом (<agent> 27.07):** личный опыт автора оригинала можно перевести в безличное без штрафа за рерайт, гейт охраняет механику хука, а чужая биография это реквизит. Если после обезличивания хук ещё работает, это случай рерайта. Если после обезличивания от хука ничего не остаётся, это случай 3 и ролик уходит в референс.

4. **ЯКОРЬ ХУКА ПОД СТОП-ЛИСТОМ КЛИЕНТА** (<agent> 30.07, карусель по донору). Хук донора стоял на слове SPF («ваш SPF остаётся на лице даже после умывания»), а SPF у бренда под бессрочным запретом: тему первыми не поднимаем. Агент заменил якорь на то, что реально остаётся на лице к вечеру (стойкий макияж, себум, городская пыль), механику и порядок слайдов сохранил, замену согласовал с заказчиком ДО работы письменно. Ход принят, правок не возвращала. Граница, общая для рилсов и каруселей:
   - **Стоп-лист тем клиента стоит ВЫШЕ гейта хука ВСЕГДА, при любом вердикте карточки.** Это не выбор между двумя канонами, это красная линия. Запрещённую тему не поднимаем ни в каком виде, включая дословную цитату донора. Гейт охраняет МЕХАНИКУ чужого текста, а не право повторить чужое слово. Третий случай подряд после 27.07 (чужая биография) и 29.07 (хук на именах), значит правило, а не исключение.
   - **Вердикт карточки это ОПИСАНИЕ того, что вышло, а не разрешение на ход.** Частая ошибка в обратную сторону: «замена якоря допустима, если стоит уникализировать». Верно наоборот, замена якоря САМА делает работу уникализацией. Тронул якорь, переставь карточку с «адаптировать» на «уникализировать» и назови причину, иначе через месяц в архиве адаптация не совпадает с донором и никто не помнит почему.
   - **Тест, замена это ещё или уже новая работа по чужому каркасу:** хук обязан работать ПО ТОЙ ЖЕ ПРИЧИНЕ. У примера причина «к вечеру на лице остаётся то, о чём ты не думаешь», и SPF, макияж, себум, пыль играют в ней одну роль, механика цела. Меняется сама причина срабатывания, значит это новая единица на чужом каркасе, и называть надо так честно.
   - **Согласование с заказчиком ДО работы, письменно, часть правила, а не личная аккуратность исполнителя.**
   - **Хвост, который легко забыть:** запрет вида «первыми не поднимаем» НЕ покрывает вопрос из комментариев по той же теме. Линию ответа согласовать с владельцем ЗАРАНЕЕ, до публикации.

**ДОНОР ФОРМАТА (правило куратора , механически с 17.08).** Если речь оригинала это
прайс-лист конкурента (чужие товарные марки, диагнозы, названия услуг), хук по нему НЕ переносится:
берётся конструкция, речь пишется своя на позициях клиента. Порог `hook_fidelity_check.py` там
недостижим арифметически (@donor_nine DcHBjmsMRm-: максимум 0.42 при пороге 0.50, все семь
потерянных слов — чужие марки и диагноз). Помечать ЯВНО и С ПРИЧИНОЙ, одним из двух способов:
```
"hook_source": "format_donor",
"hook_source_reason": "речь оригинала это чужие аптечные марки и диагноз"
```
или строкой в `editor_brief`, которая НАЧИНАЕТСЯ с пометки:
```
ДОНОР ФОРМАТА: речь оригинала это чужие аптечные марки и диагноз
```
Причина обязательна: это снятие блокирующего гейта, и она уходит в сводку клиента. Пометка без
причины и упоминание внутри фразы («НЕ ДОНОР ФОРМАТА», «не ставь ДОНОР ФОРМАТА без нужды») гейт
НЕ снимают. `--force` при этом не нужен.
**Пометка снимает перенос ХУКА, а не сам телесуфлёр:** пустой телесуфлёр у донора по-прежнему флаг.
И это НЕ замена РЕФЕРЕНС-ONLY: та означает, что телесуфлёра нет вовсе.

**Правило второго шага:** переписал хук — вторым действием правь `editor_brief`. На таймкоде 0:00 там лежит цитата хука, и после правки она остаётся старой, монтажёр снимет не то начало. `hook_fidelity_check.py` в бриф не смотрит, это ручная проверка.

CTA-триггер = кодворд ПОД ТЕМУ рилса (см. правило «Кодовое слово CTA» выше). «статья» — только по явному указанию владельца для конкретного рилса.

## Карточка пакета — первым сообщением

Первое сообщение по каждому рилсу/карусели = карточка в порядке:
1. **Ссылка на исходник.**
2. **Почему взяла** (коротко, по сути).
3. **Метрики виральности ФОРМУЛАМИ, не на словах:**
   - `ratio = просмотры / медиана аккаунта = V / M = ×R` (главный показатель: во сколько раз ролик обогнал свою медиану)
   - `score = база + медиана×3 + свежесть<48ч + длит.24-60с + триггер-комменты` (показать, какие компоненты сработали, числами)
   - просмотры / лайки / комменты / длительность / возраст
   Не объяснять выбор словами вместо цифр. Цифры и формула первичны.

Слабые по ratio ролики (например ×0.05) НЕ брать как «копировать» — нечего копировать, это флоп. Отсеивать на этапе выбора, в пакет не класть.

## HARD RULE — телесуфлёр только с РЕАЛЬНОГО транскрипта

**`transcribe.py` НЕ скачивает видео.** Он читает уже скачанное `pool/work/<code>/audio.mp3`.

дословно, рерайт ~25%) сломано, владелец такое бракует. Ровно так сгорела подборка
.

**Текст ролика достаётся всегда**, если это видео: HikerAPI `/v1/media/by/code` отдаёт

## HARD RULE — baseline + delta режим pull

**Полный pull 24 рилсов на аккаунт = ОДИН РАЗ. Дальше — только дельта.**

Зачем: каждый день тянуть по 24 рилса × 30 аккаунтов = 720 запросов в сутки. Бессмысленно — данные те же. Нужны только свежие посты + ранее посчитанная норма аккаунта.

**Baseline (разово, при добавлении аккаунта в watchlist):**
- Pull 24 последних рилса
- Считаю **медиану про:смотров** = «норма этого блогера»
- Сохраняю в `cache/watchlist_baseline.json` формат: `{username: {median_plays, max_plays, computed_at, sample_size}}`

**Delta (ежедневно):**
- Pull 1 страницы (12 свежих) по каждому аккаунту = 30 req/день вместо 720
- Сравниваю новые про:смотры с baseline-медианой → виралка = ≥3× медианы
- Если медиана аккаунта не обновлялась 7 дней — точечный rebaseline (повторный pull 24)
- Для растущих аккаунтов (followers выросли > 30%) — rebaseline сразу

**Триггеры на rebaseline:**
- Возраст baseline ≥ 7 дней
- Followers выросли > 30% с прошлого baseline
- За 7 дней не было ни одной виралки → возможно медиана съехала, надо проверить

**Watchlist hygiene (2 недели после добавления):**
- Если за 14 дней с момента baseline у аккаунта **0 виралок** (≥3× медианы) — отсев в `rejected` с причиной `no_virals_14d`.
- Это удерживает watchlist чистым и расход HikerAPI в рамках.

**Замер под вопрос владельцу переснимается В МОМЕНТ ВОПРОСА (hard, , случай <agent>).**
Отсев донора это решение владельца бренда. Агент его не принимает, поэтому вопрос уходит человеку. Между замером и
вопросом обычно проходят дни, и за эти дни половина списка оживает.
- Проверено числами: замер 13.08 дал пять кандидатов на замену, прогон того же скрипта 17.08 оставил
  двоих. `anna_chernaya_psy` и `alexandramitroshina` за это время выложили по два рилса, последний за
  2,9 дня до вопроса. Уйди старый список владельцу, ему пришёл бы как факт список, где двое из пяти
  уже работают.
- Отсюда порядок: сначала прогон свежего замера, потом формулировка вопроса, и оба в один заход.
  Замер четырёхдневной давности стареет ровно так же, как запись о живом объекте.
- Разделяй два разных состояния, они лечатся по-разному. Молчит по рилсам И по каруселям это мёртвый
  донор, его меняем. Молчит по рилсам, а карусели даёт, это КАРУСЕЛЬНЫЙ донор, его помечаем и держим.
  Один порог на оба формата выбрасывает живых поставщиков контента.
- Вопрос по всем кандидатам идёт ОДНОЙ строкой в ближайшую регулярную сводку владельцу, а не карточкой
  на каждого и не отдельным сообщением. Молчащий донор ежедневную подборку не держит по построению, он
  просто не даёт сырья, поэтому вопрос не срочный.
- Карточка, которая ждёт ответа человека, стоит в blocked с критерием снятия и датой возврата. В
  рабочем статусе она стареет и читается сторожем как простой агента.

## Стоимость HikerAPI — реальная (pay-as-you-go)

HikerAPI = pay-as-you-go, **не подписка**. Цена от $0.0006/request, средняя по нашим эндпоинтам $0.001-0.003.

Месячная нагрузка после baseline+delta оптимизации:
- 1× baseline всех 30 аккаунтов = ~120 req
- 29 дней мониторинга × 60 req (30 рилсы + 30 посты) = 1740 req
- Comments check топ-30 кандидатов/день × 30 = 900 req
- Ad-hoc (рилсы которые владелец кидает на рерайт) = ~150 req
- **Итого ~3000 req/мес = $3-9/мес** при средней цене $0.001-0.003.

## HARD RULE — окно свежести

**Только 24h → fallback 48h. НИКАКИХ 72h и дальше.**

- День 1 (новый аккаунт в watchlist): onboarding-pull последних 24 рилсов для baseline-медианы. Один раз. В отчёт НЕ идёт.
- Все последующие дни: last 24h относительно момента запуска cron (03:00 МСК).
- Если за 24h по всему watchlist <10 топовых → расширяю до 48h.
- Если за 48h всё ещё <10 → шлю сколько есть. Дальше НЕ лезу. Контент старше 48h устарел — нам не нужен.

**Why:** свежак — топливо виралки. Двое суток это предел сохранности тренда. Дальше тема уже отыграна или подхвачена массой, нет смысла переснимать.

**Реализация (вшито в код , не полагаться на ручную фильтрацию):**
- `pull_reels.py` тянет только в окне `limits.fallback_lookback_hours` (48ч) — потолок на входе, стале в пул не попадает. Раньше был баг: тянул за 7 дней.
- `pull_reels.py` читает список аккаунтов из `config/watchlist.json` (anchor+expansion=30), не хардкод. Раньше был баг: хардкод 12.
- `score.py` freshness-gate: primary `<=lookback_hours` (24ч), если набралось `>=min_primary_for_strict` (6) — строгие 24ч, иначе fallback 48ч. Старше — отсекается из выгрузки полностью. Сортировка: скор↓, при равенстве возраст↑.
- baseline median: считается в `pull_reels.py` из полного списка клипов автора и кладётся в `_top3_per_account.json:median_views`. `score.py` берёт готовый, ре-фетчит только если нет. Раньше был баг: хрупкий ре-фетч → median=None → viral_ratio пустой → побеждали старые крупняки.
- **Известный конфликт:** свежак <48ч ещё не успел набрать просмотры → viral_ratio низкий. Проверенные виралки (ratio≥3x) по природе старше 3-7 дней и режутся гейтом. Решение по «proven virals lane» (отдельное окно 5-7д под виральность) — за владелец, без его sign-off гейт не менять (это его hard-rule).

## HARD RULE — дедупликация state

**Старое не показываю никогда. Запоминаю что владелец взял или отклонил.**

State хранится в двух местах (зеркало для надёжности):
- gbrain `external_note` с тегом `morning_reels_seen` — для кросс-сессий и swarm-visibility
- локальный `cache/reels_seen.json` — быстрый filter в пайплайне

**Theme-дедуп (поверх pk-дедупа): не повторяю ТЕМУ даже от другого автора.**
- `cache/themes_seen.json` — история показанных тем `{shortcode, username, date, theme_text, embedding}`.
- `dedupe_filter.py` эмбеддит caption кандидата (multilingual-e5-large, локально) и сравнивает
  с темами за `theme_dedup_window_days` (21д) И с уже принятыми в этом прогоне. cosine >=
  `theme_similarity_threshold` (0.88) → выбрасываю. Кандидаты по убыванию скора — остаётся сильнейший.
- Карусели дедупятся против той же истории + принятых рилсов (тема не дублируется reel↔carousel).
- `mark_shown.py` пишет тему в историю ТОЛЬКО для финально показанных постов.
- Порог 0.88 откалиброван на реальных caption: ловит буквальные дубли (0.97) и парафразы (0.89+),
  но пропускает CTA-лидмагниты с общим boilerplate (кластер ~0.85). Ложный DROP дороже ложного
  KEEP → порог консервативный. Пересмотреть по мере накопления `themes_seen.json`.
- Параметры в `config/watchlist.json:limits` (`theme_*`). Helper — `scripts/lib_embed.py`.

Запись: `{shortcode, username, shown_at, status}`. Статусы:
- `shown` — показала в дайджесте, ждём решения владелец
- `taken` — владелец сказал «взял в работу» (записал / отдал монтажёру)
- `shot` — отснял и опубликовал
- `rejected` — отклонил (не подошёл / тема / сложно адаптировать)

**владелец фидбекит одной строкой:** «3, 7 взял», «5 не подошёл», «9 отснял». Я апаю status, никогда больше не показываю `taken` / `shot` / `rejected`. Статус `shown` без решения через 5 дней — авто-перевод в `rejected` (молчание = не подошло).

**Pipeline:**
1. `dedupe_filter.py` (03:15) — исключаю shortcode'ы со статусом ≠ `shown` из кандидатов
2. `mark_shown.py` (05:00) — финальные 10 + 3 пишу со статусом `shown`

2. **Противоречие между упаковкой и составом — это риск клиента, а не наша стилистическая правка.** Спрашиваю прямо: на чём основана характеристика, есть ли протокол испытания. До письменного ответа позиция не идёт в производство вообще, ни отдельным рилсом, ни в каталоге линейки, ни в каруселях, ни в воронке.
3. **Нашёл риск в УЖЕ отданном артефакте — предупреждаю людей в тот же час.** Отложенное «предупрежу, если возьмут» не работает: артефакт берут тогда, когда меня не спросили, а сессия к тому моменту уже уехала. Пишу СММ или клиенту одной строкой сразу, и отдельно говорю, что остальные позиции работают, чтобы человек не встал целиком.
4. **Сам отданный текст не переписываю, но кладу рядом стоп-пометку.** Формат: `out/_STOP_LIST.md` в одной папке с артефактами, карточкой на каждый случай (что нельзя, почему, что делать вместо, чем снимается, кто и когда поставил). Предупреждение рядом с файлом это не переписывание отданной работы, это безопасность.
5. **Донор формата ≠ донор речи.** Если вся дорожка оригинала состоит из чужих товарных названий, `hook_fidelity` по такому рилсу не гоняется вообще: берём конструкцию, пишем свою речь на позициях клиента, карточку помечаем «ДОНОР ФОРМАТА» с причиной. Молча обходить гейт нельзя, подгонять число под порог нельзя.

## Acceptance criteria

- **Дедлайн: 08:00 МСК.** Папка должна быть у владельца в чате не позже.
- **Если не успеваю — partial digest.** Отправляю готовые пакеты через `send_morning_digest.py` (с урезанным `meta.json:intro`) + отдельное сообщение «остальное будет в 09:00». Молчание и сырая выдача хуже неполного но правильного.
- **Никогда не отправлять «сырой» формат.** Если пакеты не дописаны или нет URL — лучше алерт «папка задержана, причина X, ETA Y» чем длинные text-блоки с режиссёрскими пометками.
- **Топ-10 рилсов + карусели минимум 5, до 10 (владелец ; цифры — config/watchlist.json:limits).** Дубль автора → заменяю следующим по приоритету.
- **URL рилса обязателен** в каждом `editor_brief` в конце как `РЕФЕРЕНС: https://www.instagram.com/reel/<shortcode>/`. То же для каруселей: `https://www.instagram.com/p/<shortcode>/`.
