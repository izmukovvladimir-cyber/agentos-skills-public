# Эталон-блюпринт нурчер-воронки «ФУНДАМЕНТ»

Живой референс структуры. Любая новая воронка под кодовое слово собирается ПО ЭТОМУ образцу,
чтобы не расходилась и собиралась одинаково крепко. Эталонная автоматизация лежит в ChatPlace
своим `<automation_id>` на боте `<bot_id>`, статус Active.

Это БОГАЧЕ, чем линейный вывод `cp_funnel_builder.py` (тот даёт базу welcome→sub→магнит→статья→buy1/2/3).
ФУНДАМЕНТ добавляет: мост с 2 кнопками, развилку по чтению, две ветки прогрева А/Б с пруфами,
перескок «открыл статью → сразу в продажу», обложку «что внутри», обрыв по оплате на каждом касании,
кнопки продажи на реальную оплату трипваера (атрибуция).

---

## Полный граф (что за чем)

```
ВХОД (кодворд) → приветствие
  → COND check_subscription @your_channel (<channel_id>)
        подписан → магнит
        нет → «подпишись» → петля check_subscription
  → МАГНИТ (выдача разбора из библиотеки, ссылка на hub-страницу)
  → DELAY 10 мин
  → МОСТ (2 кнопки):
        [url «Читать статью»]  → на лендинг, trackClicks + тег «открыл-статью-v2»
        [normal «Я прочитал»]  → тег «прочитал-статью-v2», ведёт в тот же следующий узел
  → DELAY 12 мин
  → РАЗВИЛКА has_tags «открыл-статью-v2»
        ДА  → COND ОПЛАТИЛ (см. cade)
        НЕТ → ветка Б (Б1)

cade  COND has_tags «ОПЛАТИЛ»
        ДА  → ПОЗДРАВЛЕНИЕ (доступ + ссылка на продукт + дубль на почту + апселл следующей ступени) → конец
        НЕТ → ОБЛОЖКА «что внутри трипваера» → А1
```

### Ветка А (прочитал, не купил) — темп 0 / +4 часа / следующий день
```
А1  кейс + пруф-карточка + кнопка оплаты трипваера   (сразу)
  → DELAY 4 часа
  → COND ОПЛАТИЛ (ДА → поздравление / НЕТ → А2)
А2  кейс + пруф + кнопка оплаты                       (+4 часа)
  → DELAY 1 день
  → COND ОПЛАТИЛ (ДА → поздравление / НЕТ → А3)
А3  финал «сейчас N ₽, после набора дороже» + пруф + кнопка оплаты   (следующий день) → конец
```

### Ветка Б (не открыл статью) — темп 0 / +2 часа / следующий день, с ПЕРЕСКОКОМ
```
Б1  «статью не открыл, там ключ» интрига + кнопка «Читать статью»   (сразу)
  → DELAY 2 часа
  → CHK1 COND has_tags «открыл-статью-v2»
        ДА  → cade (в продажу)         ← перескок
        НЕТ → Б2
Б2  кусок пользы прямо в бот + мост на статью   (+2 часа)
  → DELAY 1 день
  → CHK2 COND has_tags «открыл-статью-v2»
        ДА  → cade (в продажу)         ← перескок
        НЕТ → Б3
Б3  разворот в продажу: кейс + пруф + кнопка оплаты   (следующий день) → cade → продажа
```

**Перескок (важно):** после КАЖДОГО шага ветки Б стоит condition-проверка has_tags «открыл-статью-v2».
Кликнул «Читать статью» на любом шаге → мгновенно уходит в продающую цепочку (cade), а не досиживает
прогрев. Собирается: `messages_create(actionType="condition")` → `condition_buttons_create` (fit) →
`conditions_setup` (has_tags, tagIds=[открыл-статью-v2], fulfilledType one_or_more) → `buttons_connect`
fit→cade, not_fit→следующий шаг Б → `messages_connect` delay→condition.

## Тайминги (боевые — вернуть после любого теста!)

| узел | назначение | тип | значение |
|---|---|---|---|
| магнит→мост | b372 | 2 (мин) | 10 |
| мост→развилка | b9a1 | 2 (мин) | 12 |
| Б1→CHK1 | c6c8 | 3 (час) | 2 |
| А1→А2 | d4dd | 3 (час) | 4 |
| А2→А3 | e293 | 4 (день) | 1 |
| Б2→CHK2 | 144d | 4 (день) | 1 |

Delay = `automations_actions_setup(messageId, subActions=[{actionLabel:"delay", fields:{type,delay:"V",chosenDays:[]}}])`.
Тип: 1=сек, 2=мин, 3=час, 4=день. На тест можно временно поставить всем type2 delay=1, ПОСЛЕ — вернуть боевые.

## Пруфы (свежие карточки-хайлайтс, НЕ сырые скрины)

Пруф = оформленная неон-карточка (имя+роль, цитата, скрин в телефоне, бейдж-метрика) из каталога
хайлайтсов, сконвертить в jpg → каталог медиа сайта → deploy → грузить в ChatPlace
`media_files_upload` с прямой raw-ссылки репозитория (`raw.githubusercontent.com/<your-repo>/main/media/<file>`;
raw отдаёт сразу, не ждать Pages) → `messages_attach_media`.

Кейсы берутся свои, по одному на касание, одного человека дважды в одной воронке НЕ ставить.
Раскладка ФУНДАМЕНТа: А1 кейс 1 / А2 кейс 2 / А3 кейс 3 / Б3 кейс 4.

---

## Кнопки продажи (атрибуция)

ВСЕ кнопки оплаты = UrlButton на deep-link `https://t.me/your_bot?start=<buy-slug>`
(inline_buttons_setup subtype=url). Это уводит на проверенную платёжную воронку (Active),
где check_payment ставит тег «ОПЛАТИЛ» по факту оплаты → догрев гаснет сам, выдача в бот + дубль на почту,
покупка видна в учёте. Тег на url-клик НЕ вешать (ложно пометит кликнувших как оплативших).
Единый источник оплаты: и лендинг, и воронка платят одинаково.

## Обрыв по оплате

На каждом продающем касании (перед А2, перед А3, вход в продажу cade) стоит COND has_tags «ОПЛАТИЛ»:
ДА → поздравление (стоп). Купил на любом шаге → мгновенно в поздравление, дальше не шлём.

## Теги (id берутся из своего кабинета через `tags_list`)
- ОПЛАТИЛ = `<tag_id_paid>`
- открыл-статью-v2 = `<tag_id_opened>`
- прочитал-статью-v2 = `<tag_id_read>`

## Гота NormalButton (вшито болью)
NormalButton через `buttons_connect` ХАЙДЖЕКАЕТ дефолтный nextStepId сообщения-моста. Фикс: роутить сам
NormalButton в ТОТ ЖЕ узел, что нужен дефолту; tagIds на normal-кнопку через `inline_buttons_setup subtype=normal`.
Проверять nextStepId моста через get_detail ПОСЛЕ добавления любой NormalButton.

## get_detail большой
`automations_get_detail` превышает лимит токенов → сохраняется в файл, читать jq по узлам
(edge-map: `.steps[0].messages[] | {id, actionType, nextStepId, conditionButtons}`).
