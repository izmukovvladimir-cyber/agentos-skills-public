# product-unpack — сборка сильного мини-продукта

Скилл превращает нишу или клиента в готовый продающийся мини-продукт. Не «идею», а
собранный целиком трипваер: боль → оффер → само содержимое → цена → воронка.

Продукт по этому скиллу проходит тот же входной фильтр, что лид-магниты хаба:
**principal-уровень + ANTI-WATER GATE** (`assets/hub/CONTENT_STANDARD.md`). Мини-продукт
ОТДАЁТ рабочий инструмент, а не список «что внутри». Слабый образец (набор промптов за
маленький чек) эталоном НЕ считать, планка выше.

## ШАГ 0 (БЛОКИРУЮЩИЙ): чей это продукт

Прочитай профиль до любой сборки.
- **Воркспейс клиента** → `core/CLIENT.md`. Ниша, боли, голос/род, продукт-лестница,
  канал, бот, домен, цены, кейсы — только клиента. Чужие дефолты (чужой кодворд,
  чужой ник, чужая цена, чужой кейс, чужая платёжка) НЕ подставлять. Всплыли = брак.
- **Воркспейс владельца аккаунта** → канон его материал (TOV, воронка, хаб `your-domain.ru`,
  продукт-лестница из `core/USER.md`).

Если ниша/клиент заданы прямо в запросе (разовый продукт под чужую нишу) — работаешь по
переданным вводным, всё равно проверяя качество этими же гейтами.

## Конвейер (6 шагов, прогонять целиком)

### Шаг 1. РАСПАКОВКА (боль → спрос)

Собери карту спроса ниши/клиента. Источники по приоритету:
1. Живые данные ниши: `niche-reels-research` + `hikerapi` (что залетает у конкурентов, какие
   темы собирают комменты = где болит), архив чатов/групп через `telegram-chip`.
2. Материал клиента: его посты, продукты, отзывы, вопросы аудитории.
3. `perplexity-research` / web — язык боли, типовые возражения, готовность платить.

Выход — **карта боли** (в `scratchpad/`): топ 3-5 болей по силе, под каждой:
- дословный язык боли (как аудитория сама формулирует),
- желаемый результат (точка Б),
- за что уже платят рядом (референсные low-ticket офферы),
- триггер покупки (что толкает достать кошелёк именно сейчас).

Правило: боль ранжируется по СИЛЕ (интенсивность × частота × близость к деньгам), не по
удобству сборки. Гадать нельзя — тянешь из данных.

### Шаг 2. ИДЕИ (5-7 концептов оффера)

На каждую топ-боль сгенерируй концепт мини-продукта. Принцип **одна боль — одно обещание —
один результат за один присест**. Каждый концепт одной карточкой:
- рабочее название,
- обещание (что человек получит, конкретно и измеримо),
- формат-носитель (см. библиотеку форматов ниже),
- почему купят (какой триггер закрывает),
- ценовая вилка.

Не лепи всё в «набор промптов» по умолчанию. Формат идёт ОТ боли.

### Шаг 3. ОТБОР (спрос до сборки)

Оцени концепты, выбери 1, максимум 2. Скоринг по пяти осям (1-5 каждая):
- **Сила боли** — насколько горит.
- **Намерение купить** — платят ли за это рядом уже сейчас.
- **Мгновенность** — можно ли получить результат за один присест (трипваер = быстрый выигрыш).
- **Соответствие цене** — воспринимаемая ценность держит чек.
- **Отдаваемость** — можно ли реально вложить сам инструмент внутрь (не тизер).
Победитель = максимум суммы. Ничьи разбивай по «намерение купить».

Проверка спроса ДО сборки: под тему уже есть виральный контент/комменты/платящие рядом?
Нет сигнала — вернись к шагу 2, не собирай вслепую.

### Шаг 4. СБОРКА (сам инструмент, principal, anti-water)

Собери продукт ЦЕЛИКОМ. Это ядро, здесь халтура убивает всё.

**Гейт (оба обязаны быть «да»), из `CONTENT_STANDARD.md`:**
1. Прочитав ТОЛЬКО продукт (не переходя дальше), человек уже получил рабочий инструмент/результат?
2. Truth-match: что обещает оффер/контент-вход = ровно то, что лежит внутри?
Нет хотя бы одного — переписать глубже или сменить формат. Полуфабрикат не отдавать.

Планка (principal): «нихуя себе, вот это сильно», не «очередной бесплатный ChatGPT».
Из реальной практики, конкретика которой в открытом доступе нет, доводит до результата
(прочитал, встал, сделал), живой голос без AI-почерка.

Внутри — само содержимое: рабочие шаги с механикой и цифрами, готовые промпты, которые
возвращают АРТЕФАКТ (роль + контекст + жёсткий формат вывода + заполненный пример + обработка
краёв), заполняемые шаблоны, чек-листы с механикой. Не названия разделов, а разделы.

### Шаг 5. ОФФЕР И ЦЕНА

- **Оффер**: hook (боль дословно) → story/мостик (почему обычный путь не работает) → offer
  (что даёшь, для кого, что человек получит). «Ты», не «вы» (умолчание владельца; для клиента — по
  его голосу). Без длинных тире и «не X а Y».
- **Цена**: трипваер — низкий барьер, импульсная покупка. Ставь по воспринимаемой ценности
  и якорю к следующей ступени лестницы. Дай 1-3 ценовые точки с обоснованием (что оправдывает
  чек). Психология: круглая низкая цена как вход, продукт очевидно дороже своей цены.
- **Имя**: короткое, из языка боли, обещает результат.

### Шаг 6. УПАКОВКА И ВОРОНКА

- Продукт-магнит собери как страницу хаба: `assets/hub/content/<slug>.json` +
  `registry.json` (категория, кодворд), build.py → selfcheck.py → deploy.sh
  (для клиента — его хаб через `client-knowledge-base-site`).
- Кодворд из темы продукта, проверь на свободность ДО запекания.
- Воронка: `funnel-skeleton` / `ship` (кодворд → магнит → цепочка TG+IG,
  finish под продукт: payment/request/booking).
- Контент-вход (рилс/карусель/пост) под кодворд — по `carousel-reskinner` / `reel-reskin`,
  truth-match к продукту.

## Опорные рамки (полный синтез — `references/tripwire_frameworks.md`)

- **Трипваер продаёт смену статуса** (лид → покупатель), не выручку. Повторная покупка у
  трипваер-клиента 60-70% против 5-20% у холодного. Задача — обнулить барьер к флагману.
- **Value Equation (Хормози):** Ценность = (Мечта-результат × Вера) / (Задержка × Усилия).
  Продукт двигает верх вверх, низ вниз. Продаём результат клиента, не контент.
- **Hook-Story-Offer:** боль хука = обещание оффера = содержимое продукта. Разрыв = возвраты.
- **Value Ladder:** проектируй продукт от флагмана назад, решение трипваера обнажает
  проблему, которую закрывает флагман.
- **Бенчмарки-цели:** конверсия в трипваер 15-25%, апгрейд трипваер → основной оффер ≥20%.
- **Цена:** коридор доверия low-ticket, нижняя граница осмысленного чека. Слишком дёшево сигналит «мусор»
  (у $9.99 abandonment 78% против 41% у $47). Charm-цена (не круглая) + якорь рядом
  («часть курса за X, отдельно за …») поднимает воспринимаемую ценность ~на треть.
- **Валидация кошельком, не словами:** сигнал спроса = сохранения/вопросы «где взять»/
  предоплата, не лайки и не «интересно» на опросе.

## Библиотека форматов (формат ОТ боли, не дефолт)

| Формат | Когда брать |
|---|---|
| Готовая система/фреймворк по шагам | боль «нет системы, всё на хаосе» |
| Пак промптов (каждый возвращает артефакт) | боль «не знаю как заставить ИИ сделать X» |
| Заполняемый шаблон / воркбук | боль «не знаю с чего начать, дайте каркас» |
| Чек-лист с механикой | боль «боюсь упустить / сделать не так» |
| Разбор с вердиктом (готовый пример) | боль «не понимаю почему у меня не работает» |
| Готовый инструмент (таблица, калькулятор, notion) | боль «нужно посчитать/вести, а нечем» |
| Свайп-файл (готовые формулировки) | боль «не умею писать/говорить это» |
| Мини-курс (3-5 коротких шагов к 1 результату) | боль «хочу навык, но некогда на большой курс» |

## Чек-лист качества (перед отдачей)

- [ ] Продукт ОТДАЁТ инструмент, внутри само содержимое (не оглавление).
- [ ] Оба вопроса anti-water гейта — «да».
- [ ] Truth-match: обещание = содержимое.
- [ ] Формат выбран ОТ боли, не дефолтный список промптов.
- [ ] Промпты возвращают артефакт (роль + формат + пример + края).
- [ ] Живой голос, ноль длинных тире «—»/«–», ноль «не X а Y», ноль AI-клише.
- [ ] Цена обоснована, продукт очевидно дороже своего чека.
- [ ] Кодворд свободен, воронка собрана, контент-вход truth-match.
- [ ] Планка principal: сам бы залип. Нет — переписать.

## Что НЕ делать

- Не брать дешёвый набор промптов как эталон качества.
- Не оглавление вместо инструмента.
- Не универсальный список промптов на каждую нишу.
- Не собирать вслепую без сигнала спроса (шаг 3).
- Для клиента не подставлять чужие дефолты (шаг 0).
