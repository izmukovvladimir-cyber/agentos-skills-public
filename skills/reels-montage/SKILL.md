# reels-montage — монтаж рилсов на нашем железе

Берёт снятое вертикальное видео и собирает из него готовый рилс: субтитры слово в слово
по речи, карточка-хук в первые секунды, графические врезки. Ничего не генерирует и лицо
не трогает. Выход — MP4 1080×1920, H.264 + AAC.

Работает целиком у нас: ни браузера с логином, ни арендованной Windows, ни Veo.
Замер 19.08: 15 секунд ролика собираются за 23 секунды на 6 воркерах.

## Когда НЕ этот навык

- Нужно СГЕНЕРИТЬ видео или аватар (Veo, Sora, HeyGen) — это не сюда, там нужен браузер
  с живым логином, см. раздел «Чего у нас нет».
- Нужна карусель — `carousel-reskinner`.
- Нужно найти виралку — `niche-reels-research`.

## Движок

```
~/opt/reels-studio/bin/hf      # обёртка HyperFrames CLI (0.8.3)
~/opt/reels-studio/skills/     # 20 вендорских скиллов, читать по требованию
```

`hf` запускается ИЗ каталога проекта. Основное: `hf check`, `hf snapshot --at 8`,
`hf render`, `hf doctor`.

Вендорские скиллы читать через Read, когда нужен приём, которого нет ниже:
`hyperframes-core/SKILL.md` — контракт композиции, `hyperframes-animation` — движение,
`talking-head-recut` — врезки поверх говорящей головы, `embedded-captions` — стили
субтитров, `media-use` — музыка, звук, логотипы.

## Быстрый путь (то, ради чего навык)

```
D=~/.claude/skills/reels-montage/scripts

python3 $D/transcribe_words.py video.mp4 -o words.json

python3 $D/build_subs_reel.py \
  --clip video.mp4 --words words.json --out ./reel \
  --hook "Текст первой карточки"

cd ./reel && ~/opt/reels-studio/bin/hf check && \
  ~/opt/reels-studio/bin/hf render
```

Готовый файл ложится в `reel/renders/`.

Ключи `build_subs_reel.py`: `--accent` (цвет подсветки слова), `--band-top` (высота
полосы субтитров в px от верха), `--max-words` и `--max-chars` (длина строки),
`--hook-until` (сколько секунд висит карточка), `--duration` (обрезать по времени),
`--width/--height`.

## Обязательный порядок

1. **Посмотреть исходник глазами до сборки.** `ffmpeg -i in.mp4 -vf "fps=1/6,scale=270:-1,tile=3x2" sheet.jpg`
   и прочитать контактный лист. Ищем две вещи: где лицо (субтитры на него класть нельзя)
   и нет ли на видео УЖЕ вжжённых субтитров — вторые поверх первых читаются как брак.
2. **`hf check` до рендера, всегда.** Он ловит то, чего не видно в коде: наезд полос друг
   на друга, контраст текста, сломанный тайминг. Рендер без него это лотерея на 20 минут.
3. **`hf snapshot --at <секунда>` и посмотреть кадр.** Проверка проходит и на композиции,
   где текст лёг на подбородок.
4. Рендер последним.

## Правила формата (из боевых сборок, ломается чаще всего)

- Кадр 1080×1920. Лицо в вертикальном селфи занимает примерно y560–1190, поэтому
  карточки живут выше y540, субтитры ниже y1290. Полоса по умолчанию на 1360.
- **Правило «выше y540» отменяется постоянной плашкой-заголовком.** Замер <client-agent>
  05.09.2026: плашка на весь ролик заняла верхние 24% кадра, свободного места выше y540 не
  осталось вовсе, и первые врезки легли человеку на лицо. Когда верх занят, рабочая зона
  врезок это полоса между подбородком и субтитрами, у её кадра нижний край 1290. `hf check`
  об этом МОЛЧИТ, ловится только снимком кадра.
- Строка субтитров держится ДО начала следующей, а не «до конца своего слова плюс запас».
  Отметки Whisper пересекаются, и две полосы разом дают нечитаемое месиво.
- Каждый тайм-элемент несёт `id`. Без него композиция рендерится, но не правится в Studio.
- Одна `gsap.timeline({paused:true})` на композицию, зарегистрирована под id корня.
- Звук всегда отдельным `<audio>`, видео `muted playsinline`. Framework владеет
  проигрыванием: `play()`/`seek()` в коде композиции запрещены.
- Никаких часов, `Math.random` без сида, сети и `repeat: -1` — рендер обязан быть
  детерминированным.

Полный контракт — `hyperframes-core/SKILL.md` в каталоге движка.

## Шрифт субтитров (правка 26.08.2026, замечание оператора)

Шрифт выбирается ПОД КИРИЛЛИЦУ, а не по красоте латинского образца. Половина модных
гротесков кириллицу либо не несёт вовсе, либо несёт кустарной допиской: буквы Ж, Щ, Ё, Ы, Ъ
разъезжаются по ширине и ролик читается как самодельный.

Порядок выбора:
1. `fc-list :lang=ru family | sort -u` — что вообще стоит на машине.
2. Проверить кандидата на тяжёлых буквах, а не на слове «привет»:
   `python3 -c "from fontTools.ttLib import TTFont; f=TTFont('<путь>'); cm=f.getBestCmap(); print([c for c in 'ЖЩЁЫЪЭЮЯжщёыъ' if ord(c) not in cm])"`.
   Непустой список означает «шрифт не годится», без обсуждений.
3. Сверить глазами на снимке кадра, а не на списке символов: наличие глифа не значит
   приличную ширину и одинаковый вес.

Рабочий для караоке-субтитров: **Bebas Neue Cyrillic** (узкий капс, честная кириллица,
`~/.local/share/fonts/BebasNeueCyrillic.ttf`). Montserrat даёт кириллицу разной плотности
и на капсе выглядит хуже.

**Системный шрифт требует `@font-face`, иначе `hf check` валится.** Указать имя в
`font-family` мало: гейт движка отдаёт `font_family_without_font_face`. Лечится одной строкой
в стилях композиции (замер <client-agent> 05.09.2026, на это наступит каждый):

```css
@font-face { font-family: 'Bebas Neue Cyrillic'; src: local('Bebas Neue Cyrillic'); }
```

**Кавычки внутри `style="..."` только одинарные.** `font-family:"Bebas Neue Cyrillic"`
внутри двойных кавычек атрибута обрывает атрибут: титр теряет размер, позицию и обводку,
слова слипаются. Греп по имени шрифта при этом ЗЕЛЁНЫЙ (имя в файле есть), ловится только
снимком кадра.

## Выдача ролика человеку

- **Потолок Telegram — 50 МБ на файл, и это ограничение по РАЗМЕРУ, а не по битрейту.**
  Считать от длины: минута терпит ~6 Мбит/с, две минуты только ~3. Двухпроходное сжатие
  даёт предсказуемый размер:
  ```
  ffmpeg -i in.mp4 -c:v libx264 -preset medium -b:v 3400k -maxrate 4200k -bufsize 8400k \
    -pix_fmt yuv420p -pass 1 -an -f mp4 -y /dev/null
  ffmpeg -i in.mp4 -c:v libx264 -preset medium -b:v 3400k -maxrate 4200k -bufsize 8400k \
    -pix_fmt yuv420p -pass 2 -c:a aac -b:a 96k -movflags +faststart -y out.mp4
  ```
  Отдавать 15 Мбит/с бессмысленно вдвойне: файл не пролезет, а если пролезет — Telegram
  пережмёт сам и качество будет решать он.
- **H.264, не HEVC.** HyperFrames рендерит в hevc; для отдачи людям перекодировать.
- **Титр НИКОГДА не ложится поверх субтитра.** Это брак, который видно с первого кадра.
  Титры живут выше y540, субтитры ниже y1290, пересечение по времени проверяется снимком
  на секунде появления титра, а не на глаз по коду.
- **Мычания вырезаются ВНУТРИ фраз, не только между ними** (замечание оператора 26.08).
  «Э-э», «ну», затяжки, паузы посреди предложения. Резка по границам предложений оставляет
  их на месте, и ролик звучит нечищеным. Тайминги слов уже есть в `words.json`, резать по ним.

## Стили

`references/styles/` — библиотека из 23 стилей автомонтажа (палитра, типографика,

## Кадры, которых нет: Flow (генерация) против монтажа (сборка)

Это две разные работы, и путать их дорого. **Flow рисует кадры, которых не существует**
(описал сцену, модель выдала видео). **Монтаж собирает ролик из уже готовых кадров** и сам
ничего не рисует. Типичный ролик просит обе руки: Flow даёт материал, монтаж собирает.

Стенд поднимается своим носителем, он не живёт постоянно:

```
bin/flow-stand.sh start|stop|status      # Xvfb :99, выход через socks, x11vnc, БЕЗ порта 9223
http://<server-ip>.nip.io:6080/vnc.html # смотреть глазами, когда скрипт встал
```

**ОТКАЗ «Мы заметили подозрительную активность» ДАЁТ ЖИВОЙ ОТЛАДОЧНЫЙ ПОРТ БРАУЗЕРА**, а не
темп, не промпт и не адрес (замер 29.08.2026). При поднятом `--remote-debugging-port`
отбивались даже настоящие события X; тот же ввод на Chrome без порта прошёл с первого раза.
Поэтому стенд теперь поднимается без порта, а Flow управляется мышью и клавиатурой на уровне
X, без CDP и без Playwright:

```
flow_x11.py      РАБОЧАЯ точка входа, полный цикл без отладочного порта
                 xvenv/bin/python flow_x11.py <prompt.txt> <out.mp4>
                     [--dur 4s|6s|8s|10s] [--res 360p|720p] [--quality 720p|1080p] [--mins 12]
                 промпт можно писать ПО-РУССКИ, Flow переводит сам
flowclassic.mjs  СТАРЫЙ путь через CDP — требует порта, то есть сам вызывает отказы
flowcollect.mjs  сбор готовых результатов  flowcheck.mjs    состояние
```

Живые прогоны 29.08.2026: 1080x1920 6 с (13 МБ) и 1080x1920 8 с (9.6 МБ), около трёх минут
от запуска до файла. `--quality 1080p` это повышение разрешения на стороне Flow: генерится
720p, на диск ложится 1080x1920.

**Агентная панель Flow закрыта с 28.08.2026:** `flowCreationAgent` отдаёт 403
`PUBLIC_ERROR_UNUSUAL_ACTIVITY`, это скоринг антибота, а не доступ и не деньги. Капчи, которую
можно пройти руками, на этом пути нет вовсе (проверено живым проходом человека через VNC).

Модели Flow: `Omni 1.1 Flash` (12 бонусов, разрешение только 360p или 720p, наш выбор для
кадров под переходы) и `Veo 3.1 - Lite | Fast | Quality` (Quality 100 бонусов, кнопок
разрешения и длительности у них нет, значения задаёт сама модель).

Скрипт держит человеческий темп сам (разброс задержек, подвод курсора, посимвольный ввод) и
потолок: минимум 4 минуты между прогонами, не больше 8 в час, журнал `var/state/flow-runs.json`,
отказ кодом 13.

Скрипт опознаёт отказ по виду плитки и выходит кодом 10 сразу, бонусы Flow за него не
списывает. **Получил 10 — первым делом проверь порт** (`flow-stand.sh status` печатает
«отладочный порт 9223: не поднят (это норма)»), потом выжди и скажи оператору: повторы
ухудшают оценку профиля. Один проект = один прогон за раз.

**Ширина плитки в ленте проекта непостоянна** — каждый новый ролик ужимает ряд. Всё, что
привязано к правому краю плитки (кнопка «ещё», меню, подменю качества), считается от
замеренного края. Промах по кнопке «ещё» молча открывает редактор и уводит со страницы.

**Три грабли русского агентного UI Flow, из-за которых движок студии там НЕ работает.**
Они не косметические, на каждой скрипт встаёт молча:
1. кнопка «Добавить в запрос» появляется в DOM ТОЛЬКО под курсором на плитке;
2. кнопки диалога согласия это `div`, обычным кликом не берутся — только `elementFromPoint`;
3. чипы вложений считаются в ПРАВОЙ НИЖНЕЙ панели, а не по всей нижней полосе.

Границы, проверенные живьём: в ЕЭЗ, Британии и Швейцарии запрещено РЕДАКТИРОВАТЬ загруженное
видео (конвейер встаёт молча, поэтому выход американский); подписка Google AI Pro российской
картой не оплачивается; интерфейс русский, и любой готовый рецепт под английский UI мимо.

**Артефакт бывает СТАРШЕ правки.** На ролике «Страх» запрет субтитров вписали во все четыре
промпта, но первая часть была сгенерирована на пять минут раньше правки и несла старый дефект.
Сверять `mtime` выдачи с `mtime` источника, а не помнить, что «правку внесли».

## Цвет исходника: `--sdr` не тонмапит, а ГАСИТ

`--sdr` у HyperFrames это не тонмаппинг HDR в SDR, а срезание: картинка становится плоской и
блёклой. Без флага на HDR-исходнике пишется 20+ ГБ кадров. Значит порядок такой: сначала
привести исходник настоящим тонмаппингом (`zscale`/`tonemap` в ffmpeg), и только потом отдавать
в рендер. Флаг остаётся аварийным выходом, а не нормой.

## Чего у нас нет и не будет без отдельного решения

Генерация видео и аватаров (Google Veo/Flow, Sora, HeyGen, ElevenLabs) идёт через
браузер с живым логином либо через платный API. У нас нет ни того, ни другого:
- Flow и Sora — только браузером на машине с американским IP, подписка Google AI Pro
  российской картой не оплачивается;
- HeyGen и ElevenLabs — по API, нужны ключи. Три навыка под них уже написаны,
  включатся ключом.

Монтаж, субтитры, врезки, рендер — всё это здесь и работает без них.

## Доставка MP4 и честная эскалация Flow

- **ВСЕГДА отдавать ФАЙЛОМ, без спроса** (слово оператора 29.08.2026). Голый `.mp4` Telegram показывает встроенным видео и жмёт его, поэтому мастер упаковывается в ZIP методом `STORE` (без перекодирования и без сжатия) и уходит документом. `zip` на сервере НЕ УСТАНОВЛЕН, пакуй питоном: `python3 -c "import zipfile,sys;z=zipfile.ZipFile(sys.argv[2],'w',zipfile.ZIP_STORED);z.write(sys.argv[1],arcname=sys.argv[1].rsplit('/',1)[1]);z.close()" out.mp4 out.zip`. Внутри байт-в-байт исходный MP4. Встроенным видео отдавать только если он сам попросил превью.
- Перед выдачей проверять `ffprobe`: строго 1080×1920, H.264/AAC, звук есть, размер меньше лимита доставки.
- Сбой Flow обозначать оператору сразу, как только он подтверждён. Нельзя молча заменять запрошенные генеративные сцены HTML-графикой и сообщать о блокере только после готового рендера.
- Flow считается сработавшим только после скачивания и локальной проверки клипа. `request sent`, открытая страница или зелёный UI успехом не считаются.
- Если Flow упёрся в `401/403`, после одного повторного теста эскалировать агенту-кодеру доступ/entitlement/ключ; монтажный fallback делать только как явно обозначенный вариант.
